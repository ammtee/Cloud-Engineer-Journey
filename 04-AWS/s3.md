# Amazon S3 (Simple Storage Service)

## What It Is

S3 is object storage — designed to store and retrieve any amount of data (files, images, backups, static websites) from anywhere on the web. Unlike EBS (block storage) or EFS (file storage), S3 stores data as **objects** inside **buckets**, accessed via a flat namespace and HTTP(S) API.

## Core Concepts

| Concept | Description |
|---|---|
| **Bucket** | A top-level container for objects; globally unique name across all of AWS |
| **Object** | The actual file/data stored, plus metadata; identified by a unique key |
| **Key** | The full path/name of an object within a bucket (e.g., `images/profile.png`) |
| **Region** | Buckets live in a specific AWS region for latency and compliance reasons |

## Storage Classes

| Class | Use Case | Retrieval |
|---|---|---|
| **S3 Standard** | Frequently accessed data | Milliseconds |
| **S3 Intelligent-Tiering** | Unknown/changing access patterns | Automatic, milliseconds |
| **S3 Standard-IA** | Infrequent access, needs fast retrieval | Milliseconds |
| **S3 One Zone-IA** | Infrequent, non-critical (single AZ) | Milliseconds |
| **S3 Glacier Instant Retrieval** | Archive, needs occasional fast access | Milliseconds |
| **S3 Glacier Flexible Retrieval** | Archive, rarely accessed | Minutes to hours |
| **S3 Glacier Deep Archive** | Long-term archive, compliance | Hours (cheapest option) |

**Lifecycle policies** can automatically transition objects between classes (e.g., move to Glacier after 90 days) to reduce cost.

## Bucket Policy vs. ACL vs. IAM Policy

| | Scope | Attached To |
|---|---|---|
| **IAM Policy** | Controls what an IAM identity can do across AWS | User/Group/Role |
| **Bucket Policy** | Controls who can access a specific bucket | The bucket itself |
| **ACL (legacy)** | Object/bucket-level permissions | Object or bucket (mostly deprecated in favor of policies) |

## Versioning

When enabled, S3 keeps every version of an object instead of overwriting it — protects against accidental deletion/overwrite. Deleted objects get a "delete marker" instead of being permanently removed (unless explicitly permanently deleted).

## Basic Commands (AWS CLI)

```bash
# Create a bucket
aws s3 mb s3://my-unique-bucket-name

# Upload a file
aws s3 cp myfile.txt s3://my-unique-bucket-name/

# Sync a local folder to a bucket
aws s3 sync ./local-folder s3://my-unique-bucket-name/

# List objects
aws s3 ls s3://my-unique-bucket-name/

# Enable versioning
aws s3api put-bucket-versioning \
  --bucket my-unique-bucket-name \
  --versioning-configuration Status=Enabled
```

## Static Website Hosting

S3 can serve a static website directly (HTML/CSS/JS) without a server:

```bash
aws s3 website s3://my-unique-bucket-name/ \
  --index-document index.html \
  --error-document error.html
```

This is the foundation of the **Cloud Resume Challenge** project later in this repository — hosting a resume site on S3, fronted by CloudFront and Route 53.

## Security Essentials

- **Block Public Access** is enabled by default on new buckets — keep it on unless you specifically need public content (like a static website)
- Use **bucket policies** for cross-account or public access rules, **IAM policies** for controlling what your own users/roles can do
- Enable **default encryption** (SSE-S3 or SSE-KMS) so all objects are encrypted at rest automatically
- Enable **versioning** on important buckets to protect against accidental deletion

## Best Practices

- Never make a bucket public unless it's explicitly meant to serve public content
- Use lifecycle rules to automatically move old data to cheaper storage classes
- Enable **S3 Server Access Logging** or CloudTrail data events for auditing
- Use **presigned URLs** to grant temporary access to private objects instead of making them public
- Enable **MFA Delete** on critical buckets to prevent accidental/malicious deletion

## Interview Prep

**Q: What's the difference between S3 and EBS?**
S3 is object storage accessed over HTTP(S), designed for storing files/data at massive scale with high durability (11 nines) — it's not attached to a single instance. EBS is block storage attached to a single EC2 instance, behaving like a traditional hard drive, used for OS volumes and databases needing low-latency block-level access.

**Q: How would you make an S3 bucket serve a static website securely?**
Enable static website hosting on the bucket, but instead of making the bucket itself fully public, put CloudFront in front of it with an Origin Access Control (OAC) so only CloudFront can read from the bucket. This adds HTTPS, caching, and keeps the bucket itself locked down.

**Q: What are S3 storage classes, and why do they matter for cost?**
They let you match storage cost to actual access patterns — frequently accessed data stays in S3 Standard, while rarely accessed data can move to Glacier tiers for a fraction of the cost. Lifecycle policies automate these transitions based on object age, which is a common cost-optimization talking point in interviews.

**Q: What does S3 versioning protect against, and what doesn't it protect against?**
It protects against accidental overwrites and deletions by keeping every version of an object. It does *not* protect against a bucket being deleted entirely (though MFA Delete adds friction there), and it doesn't reduce storage costs — old versions still count toward storage unless you set lifecycle rules to expire them.
